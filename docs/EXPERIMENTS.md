# Experiment protocol (v0.1)

## Research question

Can a compact CPU neural network learn transition physics and, when used as a simulator in a fixed planner, solve more held-out mazes than a greedy reactive baseline?

## Ground truth and holdout

- Real transition dynamics are defined in `world.py:Maze.move()`.
- Training data are generated by enumerating actual transitions from a seeded collection of procedurally generated, solvable mazes.
- Evaluation mazes use a different seed and are checked for non-overlapping layouts.
- Planning builds predicted transitions solely from the neural model, not from `Maze.move()` or `Maze.blocked()` for candidate successors.
- Only an independent replay with `Maze.move()` determines success.

## Comparisons

1. Model move prediction vs always-pick-majority label.
2. Learned-world-model A* planning vs one-step greedy Manhattan baseline (greedy may read real local legal moves).
3. The same A* planner with randomly initialized neural dynamics (a learning ablation).
4. Oracle A* via true dynamics establishes a navigation ceiling, not a competitor.

These comparisons **cannot** attribute performance specifically to latent neural reasoning versus generic search. A stronger matched-planner non-neural baseline is a required future test.

## Threats to validity

- Static environments are extremely simple and fully observable.
- The network learns an almost local collision rule. It does not learn to generate arbitrary code or reason over natural language.
- Rollouts are on a discretized explicit state space; there is no open-ended emergent thought process.
- Search compute cost is not normalized against the greedy baseline. Do not present this as equal-budget superiority.
- Evaluation currently uses one small set of seeds unless you rerun. For publication-grade evidence use multiple pre-registered seeds, confidence intervals, and new task families.
- No customer data, private repository artifacts, or external API calls are necessary.

## Acceptance of v0.1

- Tests execute with exit 0.
- Training loss is computed from actual updates.
- Saved weights reload without changing predictions.
- Evaluation input layouts are disjoint from training layouts.
- Generated evaluation report includes transition accuracy and real replay success counts, including failures.
- No claim of general reasoning or usefulness to a Coder model without direct A/B evidence.
